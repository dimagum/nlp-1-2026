# 15. In-context learning: zero-shot, few-shot, chain-of-thought

> [!summary] Суть
> - **In-context learning (ICL)** — способность LLM решать новую задачу по описанию и/или примерам **в промпте, без обновления весов**.
> - **Zero-shot**: только инструкция. **Few-shot**: инструкция + $k$ примеров «вход → выход» (демонстраций). Ярко эффект показан в GPT-3; он **растёт с размером модели**.
> - **Chain-of-Thought (CoT)**: модель показывает (или её просят показать) **промежуточные шаги рассуждения** перед ответом. Это сильно помогает в арифметике, логике и многошаговых задачах, особенно у больших моделей.
> - **Вариации**: zero-shot CoT («Давай рассуждать шаг за шагом»), **self-consistency** (несколько цепочек + голосование), Tree-of-Thoughts, ReAct (рассуждения + вызовы инструментов).
> - ICL **чувствителен** к формулировке, порядку и выбору примеров.

> [!tip] Интуиция
> **Few-shot — образец документа новому сотруднику** вместо курса обучения: пара заполненных примеров, и формат понятен. Модель не учится в смысле изменения весов: она **узнаёт** задачу, которую в каком-то виде уже видела при предобучении.
>
> **CoT — решение на черновике.** Каждый записанный шаг — дополнительное «время подумать»: вычисления на один токен у модели фиксированы, значит, больше токенов — больше вычислений. Плюс промежуточные результаты не нужно держать «в голове».

## Подробнее

### Форматы
**Zero-shot:**
```
Определи тональность отзыва (позитивный/негативный).
Отзыв: Доставка опоздала на неделю.
Тональность:
```
**Few-shot:**
```
Отзыв: Всё пришло вовремя, качество отличное. → позитивный
Отзыв: Сломалось через два дня. → негативный
Отзыв: Доставка опоздала на неделю. →
```
**Few-shot CoT** (в демонстрации есть рассуждение):
```
В: У Маши было 5 яблок, она купила 2 пакета по 3 яблока. Сколько стало?
О: Сначала было 5. Два пакета по 3 — это 6. 5 + 6 = 11. Ответ: 11.
В: <новая задача>
О:
```
**Zero-shot CoT** (Kojima et al., 2022): к вопросу добавляют «Let's think step by step».

### Что влияет на few-shot
- **Формат и пространство меток** важнее правильности самих меток: Min et al. (2022) показали, что случайные метки в демонстрациях снижают качество лишь немного.
- **Порядок примеров** (recency bias: модель тянется к метке последнего примера) и **баланс меток** (majority label bias). Помогает калибровка: Zhao et al. (2021), «Calibrate Before Use».
- **Выбор примеров**: примеры, похожие на запрос (kNN по эмбеддингам), работают лучше случайных.
- Число примеров $k$ ограничено длиной контекста.

### Почему ICL вообще работает (гипотезы)
- **Неявный байесовский вывод**: модель по примерам определяет латентную «концепцию» задачи (Xie et al., 2021).
- **ICL как неявный градиентный спуск**: для линейных задач forward-проход трансформера может реализовать шаг GD (von Oswald et al., 2022).
- **Induction heads** (Olsson et al., 2022): головы внимания, реализующие копирование паттерна «[A][B] … [A] → [B]».
- Способность проявляется **с ростом масштаба** модели.

### Chain-of-Thought и развитие
- **Wei et al. (2022)**: few-shot демонстрации с рассуждениями. Эффект появляется у моделей порядка ~100B параметров; маленьким моделям CoT может даже вредить.
- **Self-consistency** (Wang et al., 2022): сэмплируем $N$ цепочек при $T>0$ и выбираем ответ большинством голосов.
- **Least-to-most**: разбить задачу на подзадачи и решать их по очереди.
- **Tree of Thoughts**: поиск по дереву вариантов рассуждения с самооценкой.
- **ReAct**: цикл Thought → Action (поиск, калькулятор, API) → Observation → … Основа агентов.
- **Reasoning-модели** (o1, DeepSeek-R1): привычка рассуждать встроена обучением с подкреплением.
- **Ограничения**: цепочка может быть **неверной, но убедительной** (unfaithful CoT), и она стоит больше токенов.

### ICL vs fine-tuning
| | ICL | Fine-tuning |
|---|---|---|
| Обновление весов | нет | да |
| Данных нужно | 0–десятки примеров | сотни–тысячи |
| Стоимость | ноль на обучение, дорогой инференс (длинный промпт) | обучение дорого, инференс дешевле |
| Качество | хорошее у больших моделей | обычно выше на узкой задаче |
| Гибкость | менять задачу можно мгновенно | на каждую задачу — своя модель или адаптер ([[16 PEFT]]) |

> [!question]- Доп. вопросы
> - **ICL — это обучение?** В смысле изменения весов — нет. Это условное предсказание: модель «настраивается» на задачу внутри forward-прохода.
> - **Почему CoT помогает?** Больше вычислений на задачу, декомпозиция на шаги и формат, похожий на решения из обучающих данных.
> - **Когда few-shot хуже zero-shot?** Когда примеры плохо подобраны, несбалансированы или сбивают модель с формата; у instruct-моделей хорошая инструкция иногда эффективнее примеров.
